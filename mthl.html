    6.1. المثال 1

    6.1.1. المشكلة

    يجب أن تسمح هذه التطبيق للمستخدم بحساب ضريبته. نضع أنفسنا في حالة مبسطة لمكلف لا يملك سوى راتبه ليصرح به (أرقام 2004 للدخل لعام 2003):

    6.1.2. هيكل MVC للتطبيق

    ستكون بنية MVC للتطبيق كما يلي:

    ستقوم الصفحة [main.aspx] بدور وحدة التحكم. ستكون هناك ثلاثة إجراءات ممكنة:

    • init: تتوافق مع الطلب الأول للعميل. سيعرض وحدة التحكم العرض [formulaire.aspx]
    • calcul: يتوافق مع طلب حساب الضريبة. إذا كانت بيانات نموذج الإدخال صحيحة، يتم حساب الضريبة باستخدام فئة الأعمال [impots]. يعيد وحدة التحكم إلى العميل العرض [formulaire.aspx] كما تم التحقق من صحته مع إضافة الضريبة المحسوبة. إذا كانت بيانات نموذج الإدخال غير صحيحة، فستعيد وحدة التحكم العرض [erreurs.aspx] مع قائمة بالأخطاء ورابط للعودة إلى النموذج.
    • العودة: تعني العودة إلى النموذج بعد حدوث خطأ. يعرض المراقب العرض [formulaire.aspx] كما تم التحقق من صحته قبل حدوث الخطأ.

    لا يعرف وحدة التحكم [main.aspx] أي شيء عن حساب الضرائب. إنها مسؤولة فقط عن إدارة الحوار بين العميل والخادم وتنفيذ الإجراءات التي يطلبها العميل. بالنسبة للإجراء [calcul]، سيعتمد على فئة الأعمال [impot].

    6.1.3. فئة الأعمال

    سيتم تعريف فئة الضرائب على النحو التالي:

    
' مساحات الأسماء المستوردة
Imports System

' فئة
Namespace st.istia.univangers.fr
    Public Class impot
        Private limites(), coeffR(), coeffN() As Decimal

        ' المنشئ
        Public Sub New(ByRef source As impotsData)
            ' البيانات اللازمة لحساب الضريبة
             ' تأتي من مصدر خارجي [source]
             ' يتم استردادها - قد يكون هناك استثناء
            Dim data() As Object = source.getData
            limites = CType(data(0), Decimal())
            coeffR = CType(data(1), Decimal())
            coeffN = CType(data(2), Decimal())
        End Sub

         ' حساب الضريبة
        Public Function calculer(ByVal marié As Boolean, ByVal nbEnfants As Integer, ByVal salaire As Long) As Long
             ' حساب عدد الحصص
            Dim nbParts As Decimal
            If marié Then
                nbParts = CDec(nbEnfants) / 2 + 2
            Else
                nbParts = CDec(nbEnfants) / 2 + 1
            End If
            If nbEnfants >= 3 Then
                nbParts += 0.5D
            End If
             ' حساب الدخل الخاضع للضريبة و"الحصة العائلية"
            Dim revenu As Decimal = 0.72D * salaire
            Dim QF As Decimal = revenu / nbParts
             ' حساب الضريبة
            limites((limites.Length - 1)) = QF + 1
            Dim i As Integer = 0
            While QF > limites(i)
                i += 1
            End While
            Return CLng(revenu * coeffR(i) - nbParts * coeffN(i))
        End Function
    End Class
End Namespace

    كائن ضريبة من خلال تزويد منشئه بمصدر بيانات من النوع [impotsData]. تحتوي هذه الفئة على طريقة عامة [getData] تسمح بالحصول على الجداول الثلاثة للبيانات اللازمة لحساب الضريبة والتي تم عرضها سابقًا. يمكن لهذه الطريقة معالجة استثناء إذا تعذر الحصول على البيانات أو إذا تبين أنها غير صحيحة. بمجرد إنشاء الكائن [impot]، يمكن استدعاء طريقة calculer الخاصة به بشكل متكرر، والتي تحسب ضريبة المكلف بناءً على حالته الاجتماعية (متزوج أم لا)، وعدد أطفاله، وراتبه السنوي.

    6.1.4. فئة الوصول إلى البيانات

    فئة [impotsData] هي الفئة التي تسمح بالوصول إلى البيانات. وهي فئة مجردة. يجب إنشاء فئة مشتقة لكل مصدر بيانات جديد محتمل (جداول، ملفات مسطحة، قواعد بيانات، وحدة التحكم، ...). تعريفها هو كما يلي:

    
Imports System.Collections

Namespace st.istia.univangers.fr
    Public MustInherit Class impotsData
        Protected limites() As Decimal
        Protected coeffr() As Decimal
        Protected coeffn() As Decimal
        Protected checked As Boolean
        Protected valide As Boolean

        ' طريقة الوصول إلى البيانات
        Public MustOverride Function getData() As Object()

        ' طريقة التحقق من البيانات
        Protected Function checkData() As Integer
            ' التحقق من البيانات المكتسبة
            ' يجب أن تكون هناك بيانات
            valide = Not limites Is Nothing AndAlso Not coeffr Is Nothing AndAlso Not coeffn Is Nothing
            If Not valide Then Return 1
            ' يجب أن يكون لدينا 3 جداول بنفس الحجم
            If valide Then valide = limites.Length = coeffr.Length AndAlso limites.Length = coeffn.Length
            If Not valide Then Return 2
            ' يجب ألا تكون الجداول فارغة
            valide = limites.Length <> 0
            If Not valide Then Return 3
            ' يجب أن يحتوي كل جدول على عناصر >=0 وبترتيب تصاعدي
            valide = check(limites, limites.Length - 1) AndAlso check(coeffr, coeffr.Length) AndAlso check(coeffn, coeffn.Length)
            If Not valide Then Return 4
            ' كل شيء على ما يرام
            Return 0
        End Function

        ' تحقق من صحة محتوى المصفوفة
        Protected Function check(ByRef tableau() As Decimal, ByVal n As Integer) As Boolean
            ' يجب أن تكون العناصر n الأولى في المصفوفة >=0 وبترتيب تصاعدي صارم
            If tableau(0) < 0 Then Return False
            For i As Integer = 1 To n - 1
                If tableau(i) <= tableau(i - 1) Then Return False
            Next
            ' صحيح
            Return True
        End Function
    End Class
End Namespace

    تحتوي الفئة على السمات المحمية التالية:

    limites
    جدول حدود شرائح الضرائب
    coeffr
    جدول المعاملات المطبقة على الدخل الخاضع للضريبة
    coeffn
    جدول المعاملات المطبقة على عدد الحصص
    checked
    قيمة منطقية تشير إلى ما إذا كانت البيانات (الحدود، المعاملات، المعاملات) قد تم التحقق منها
    valide
    قيمة منطقية تشير إلى ما إذا كانت البيانات (الحدود، coeffr، coeffn) صالحة

    لا تحتوي الفئة على منشئ. وتحتوي على طريقة مجردة [getData] يجب على الفئات المشتقة تنفيذها. وتتمثل وظيفة هذه الطريقة في:

    • تعيين قيم للمصفوفات الثلاثة limits و coeffr و coeffn
    • إطلاق استثناء إذا تعذر الحصول على البيانات أو إذا تبين أنها غير صالحة.

    توفر الفئة الطريقتين المحميتين [checkData] و [check] اللتين تتحققان من صحة السمات (limites، coeffr، coeffn). وهذا يعفي الفئات المشتقة من تنفيذها. سيكون عليها فقط استخدامها.

    ستكون الفئة المشتقة الأولى التي سنستخدمها هي التالية:

    
Imports System.Collections
Imports System

Namespace st.istia.univangers.fr
    Public Class impotsArray
        Inherits impotsData

        ' منشئ بدون وسيطة
        Public Sub New()
            ' تهيئة المصفوفات باستخدام الثوابت
            limites = New Decimal() {4262D, 8382D, 14753D, 23888D, 38868D, 47932D, 0D}
            coeffr = New Decimal() {0D, 0.0683D, 0.1914D, 0.2826D, 0.3738D, 0.4262D, 0.4809D}
            coeffn = New Decimal() {0D, 291.09D, 1322.92D, 2668.39D, 4846.98D, 6883.66D, 9505.54D}
            checked = True
            valide = True
        End Sub

        ' منشئ مع ثلاثة مصفوفات كمدخلات
        Public Sub New(ByRef limites() As Decimal, ByRef coeffr() As Decimal, ByRef coeffn() As Decimal)
            ' يتم تخزين البيانات
            Me.limites = limites
            Me.coeffr = coeffr
            Me.coeffn = coeffn
            checked = False
        End Sub

        Public Overrides Function getData() As Object()
            ' التحقق من البيانات عند الضرورة
            Dim erreur As Integer
            If Not checked Then erreur = checkData() : checked = True
            ' إذا كانت غير صالحة، يتم إثارة استثناء
            If Not valide Then Throw New Exception("Les données des tranches d'impôts sont invalides (" + erreur.ToString + ")")
            ' وإلا يتم إرجاع المصفوفات الثلاثة
            Return New Object() {limites, coeffr, coeffn}
        End Function
    End Class
End Namespace

    تحتوي هذه الفئة المسماة [impotsArray] على منشئين:

    • منشئ بدون وسيطة يقوم بتهيئة سمات (الحدود، coeffr، coeffn) للفئة الأساسية باستخدام مصفوفات مبرمجة بشكل ثابت
    • منشئ يقوم بتهيئة سمات (limites,coeffr,coeffn) للفئة الأساسية باستخدام مصفوفات يتم تمريرها إليه كمعلمات

    تكتفي الطريقة [getData]، التي ستسمح للفئات الخارجية بالحصول على المصفوفات (limites، coeffr، coeffn)، بالتحقق من صحة المصفوفات الثلاث باستخدام الطريقة [checkData] للفئة الأساسية. وتطلق استثناءً إذا كانت البيانات غير صالحة.

    6.1.5. اختبارات فئات الأعمال وفئات الوصول إلى البيانات

    من المهم ألا تتضمن تطبيقات الويب سوى فئات الأعمال وفئات الوصول إلى البيانات التي تم التحقق من صحتها. وبذلك يمكن أن تركز مرحلة تصحيح أخطاء تطبيق الويب على جزء وحدة التحكم وطرق العرض. قد يكون برنامج الاختبار كما يلي:

    
' خيارات
Option Strict On
Option Explicit On 

' مساحات الأسماء
Imports System
Imports Microsoft.VisualBasic

Namespace st.istia.univangers.fr
    Module test
        Sub Main()
             ' برنامج تفاعلي لحساب الضرائب
             ' يقوم المستخدم بإدخال ثلاث بيانات عبر لوحة المفاتيح: متزوج nbEnfants الراتب
             ' ثم يعرض البرنامج الضريبة المستحقة
            Const syntaxe As String = "syntaxe : marié nbEnfants salaire" + ControlChars.Lf + "marié : o pour marié, n pour non marié" + ControlChars.Lf + "nbEnfants : nombre d'enfants" + ControlChars.Lf + "salaire : salaire annuel en F"

             ' إنشاء كائن ضريبة
            Dim objImpôt As impot = Nothing
            Try
                objImpôt = New impot(New impotsArray)
            Catch ex As Exception
                Console.Error.WriteLine(("L'erreur suivante s'est produite : " + ex.Message))
                Environment.Exit(1)
            End Try
            ' حلقة لا نهائية
            Dim marié As String
            Dim nbEnfants As Integer
            Dim salaire As Long
            While True
                ' يُطلب إدخال معلمات حساب الضريبة
                Console.Out.Write("Paramètres du calcul de l'impôt au format marié nbEnfants salaire ou rien pour arrêter :")
                Dim paramètres As String = Console.In.ReadLine().Trim()
                ' هل هناك ما يجب فعله؟
                If paramètres Is Nothing OrElse paramètres = "" Then
                    Exit While
                End If
                ' التحقق من عدد المعلمات في السطر الذي تم إدخاله
                Dim erreur As Boolean = False
                Dim args As String() = paramètres.Split(Nothing)
                Dim nbParamètres As Integer = args.Length
                If nbParamètres <> 3 Then
                    Console.Error.WriteLine(syntaxe)
                    erreur = True
                End If
                ' التحقق من صحة المعلمات
                If Not erreur Then
                    ' متزوج
                    marié = args(0).ToLower()
                    If marié <> "o" And marié <> "n" Then
                        erreur = True
                    End If
                    ' nbEnfants
                    Try
                        nbEnfants = Integer.Parse(args(1))
                        If nbEnfants < 0 Then
                            Throw New Exception
                        End If
                    Catch
                        erreur = True
                    End Try
                    ' الراتب
                    Try
                        salaire = Integer.Parse(args(2))
                        If salaire < 0 Then
                            Throw New Exception
                        End If
                    Catch
                        erreur = True
                    End Try
                End If
                 ' إذا كانت المعلمات صحيحة - يتم حساب الضريبة
                If Not erreur Then
                    Console.Out.WriteLine(("impôt=" & objImpôt.calculer(marié = "o", nbEnfants, salaire) & " euro(s)"))
                Else
                    Console.Error.WriteLine(syntaxe)
                End If
            End While
        End Sub
    End Module
End Namespace

    يطلب التطبيق من المستخدم إدخال المعلومات الثلاث اللازمة لحساب ضريبته عبر لوحة المفاتيح:

    • حالته الاجتماعية: o للمتزوج، n لغير المتزوج
    • عدد أطفاله
    • راتبه السنوي

    يتم حساب الضريبة باستخدام كائن من النوع [impot] يتم إنشاؤه فور تشغيل التطبيق:

    
             ' إنشاء كائن ضريبة
            Dim objImpôt As impot = Nothing
            Try
                objImpôt = New impot(New impotsArray)
            Catch ex As Exception
                Console.Error.WriteLine(("L'erreur suivante s'est produite : " + ex.Message))
                Environment.Exit(1)
            End Try

    كمصدر للبيانات، يتم استخدام كائن من النوع [impotsArray]. يتم استخدام منشئ هذه الفئة بدون حجج، والذي يوفر الجداول الثلاثة (limites، coeffr، coeffn) بقيم "ثابتة". يمكن أن يؤدي إنشاء كائن [impot] نظريًا إلى حدوث استثناء، لأن الكائن سيطلب البيانات (limites، coeffr، coeffn) من مصدر البيانات الذي تم تمريره كمعلمة، وقد يؤدي الحصول على هذه البيانات إلى حدوث استثناء. ويحدث هنا أن طريقة الحصول على البيانات (الترميز الثابت) لا يمكن أن تسبب استثناءً. ومع ذلك، فقد تركنا إدارة هذا الاستثناء من أجل لفت انتباه القارئ إلى احتمال أن يكون الكائن [impot] قد تم إنشاؤه بشكل خاطئ.

    • [global.asax] الذي يتلقى، بحكم بنية ASP.NET، أي طلب موجه إلى التطبيق
    • [main.aspx] الذي يتلقى أيضًا، بناءً على قرار المطور، أي طلب موجه إلى التطبيق

    • يجب أن يكون الحقل [txtEnfants] موجودًا وأن يكون عددًا صحيحًا >=0
    • يجب أن يكون الحقل [txtSalaire] موجودًا وأن يكون عددًا صحيحًا >=0

    إذا تبين أن البيانات المدخلة غير صالحة، يقوم المراقب بعرض العرض [erreurs.aspx] بعد أن يكون قد وضع مسبقًا في السياق القيم المتوقعة من قبله:

    • يتم وضع رسائل الخطأ في كائن [ArrayList]، الذي يتم وضعه بعد ذلك في السياق [Context.Items("erreurs")]
    • يتم أيضًا وضع عنوان URL لرابط العودة ونص هذا الرابط في السياق.

    من المهم اختبار تطبيقات الويب باستخدام عملاء آخرين غير المتصفحات. إذا أرسلنا إلى متصفح نموذجًا مع معلمات ليتم إرسالها عند التحقق من صحته، فسيقوم المتصفح بإعادة إرسال قيم هذه المعلمات إلى الخادم. قد لا يقوم عميل آخر بذلك، وبالتالي سيتلقى الخادم طلبًا تفتقد فيه بعض المعلمات. يجب أن يعرف الخادم ما يجب فعله في هذه الحالة. مثال آخر هو عمليات التحقق من الإدخال التي تتم من جانب العميل. إذا كان النموذج يحتوي على بيانات يجب التحقق منها، فيمكن إجراء هذا التحقق من جانب العميل بفضل البرامج النصية المضمنة في المستند الذي يحتوي على النموذج. لن يقوم المتصفح بإرسال النموذج إلا إذا كانت جميع البيانات التي تم التحقق منها من جانب العميل صالحة. قد نميل، من جانب الخادم، إلى افتراض أننا سنستقبل بيانات تم التحقق منها، وبالتالي لا نرغب في إجراء هذا التحقق مرة ثانية. سيكون هذا خطأً. في الواقع، قد يرسل عميل غير المتصفح بيانات غير صالحة إلى الخادم، وبالتالي قد يتصرف تطبيق الويب بشكل غير متوقع. سنوضح هذه النقاط باستخدام العميل [curl].

    ستوجد البيانات في جدول يسمى [IMPOTS] في قاعدة بيانات MySQL تسمى [dbimpots]. سيكون محتوى هذا الجدول كما يلي:

    مالك قاعدة البيانات هو المستخدم [admimpots] بكلمة مرور [mdpimpots]. نقوم بربط مصدر بيانات ODBC بهذه القاعدة. قبل القيام بذلك، دعونا نستعرض أولاً الطرق المختلفة للوصول إلى قاعدة البيانات باستخدام منصة .NET.

    من أجل تجنب الحاجة إلى إعادة كتابة تطبيق مكتوب لقاعدة بيانات B1 في حالة الترحيل إلى قاعدة بيانات B2 مختلفة، تم بذل جهد لتوحيد واجهة I1. في حالة استخدام قواعد بيانات تستخدم برامج تشغيل "معيارية"، سيتم توفير قاعدة البيانات B1 مع برنامج تشغيل P1، وقاعدة البيانات B2 مع برنامج تشغيل P2، وستكون واجهة I1 لهذين البرنامجين متطابقة. وبالتالي لن يكون هناك حاجة لإعادة كتابة التطبيق. وبذلك يمكن، على سبيل المثال، ترحيل قاعدة بيانات ACCESS إلى قاعدة بيانات MySQL دون تغيير التطبيق.

    Public Class impotsODBC
        Inherits impotsData

        ' متغيرات المثيل
        Protected DSNimpots As String

        ' المنشئ
        Public Sub New(ByVal DSNimpots As String)
            ' يتم تدوين المعلومات الثلاثة
            Me.DSNimpots = DSNimpots
        End Sub

        Public Overrides Function getdata() As Object()
            ' تقوم بتهيئة الجداول الثلاثة limits و coeffr و coeffn انطلاقًا من
            ' محتوى الجدول [impots] في قاعدة البيانات ODBC DSNimpots
            ' الحدود، coeffr، coeffn هي الأعمدة الثلاثة في هذا الجدول
            ' يمكن أن تطلق استثناءات متنوعة

            Dim connectString As String = "DSN=" + DSNimpots + ";"         ' chaîne de connexion à la base
            Dim impotsConn As OdbcConnection = Nothing         ' la connexion
            Dim sqlCommand As OdbcCommand = Nothing         ' la commande SQL
            ' الاستعلام SELECT
            Dim selectCommand As String = "select limites,coeffr,coeffn from impots"
            ' جداول لاسترداد البيانات
            Dim aLimites As New ArrayList
            Dim aCoeffR As New ArrayList
            Dim aCoeffN As New ArrayList
            Try
                ' يتم محاولة الوصول إلى قاعدة البيانات
                impotsConn = New OdbcConnection(connectString)
                impotsConn.Open()
                ' يتم إنشاء كائن أمر
                sqlCommand = New OdbcCommand(selectCommand, impotsConn)
                ' يتم تنفيذ الاستعلام
                Dim myReader As OdbcDataReader = sqlCommand.ExecuteReader()
                ' استغلال الجدول المسترد
                While myReader.Read()
                    ' يتم وضع بيانات السطر الحالي في الجداول
                    aLimites.Add(myReader("limites"))
                    aCoeffR.Add(myReader("coeffr"))
                    aCoeffN.Add(myReader("coeffn"))
                End While
                ' تحرير الموارد
                myReader.Close()
                impotsConn.Close()
            Catch e As Exception
                Throw New Exception("Erreur d'accès à la base de données (" + e.Message + ")")
            End Try
            ' يتم وضع الجداول الديناميكية في جداول ثابتة
            Me.limites = New Decimal(aLimites.Count - 1) {}
            Me.coeffr = New Decimal(aLimites.Count - 1) {}
            Me.coeffn = New Decimal(aLimites.Count - 1) {}
            Dim i As Integer
            For i = 0 To aLimites.Count - 1
                limites(i) = Decimal.Parse(aLimites(i).ToString())
                coeffR(i) = Decimal.Parse(aCoeffR(i).ToString())
                coeffN(i) = Decimal.Parse(aCoeffN(i).ToString())
            Next i
            ' يتم التحقق من البيانات المكتسبة
            Dim erreur As Integer = checkData()
            ' إذا كانت البيانات غير صالحة، يتم إصدار استثناء
            If Not valide Then Throw New Exception("Les données des tranches d'impôts sont invalides (" + erreur.ToString + ")")
            ' وإلا يتم إرجاع الجداول الثلاثة
            Return New Object() {limites, coeffr, coeffn}
        End Function
    End Class

    أظهرت الأمثلة السابقة، من خلال حالة ملموسة، الآليات المستخدمة بشكل شائع في تطوير الويب. استخدمنا بشكل منهجي بنية MVC لفائدتها التعليمية. كان من الممكن معالجة هذه الأمثلة نفسها بطريقة مختلفة وربما أبسط بدون هذه البنية. لكن هذه البنية توفر مزايا كبيرة بمجرد أن يصبح التطبيق معقدًا بعض الشيء مع وجود صفحات متعددة.

    يمكننا متابعة أمثلةنا بطرق مختلفة. وإليك بعض منها:

    • قد يرغب المستخدم في الاحتفاظ بمحاكياته بمرور الوقت. قد يقوم بإجراء محاكيات في اليوم J ويمكنه العثور عليها في اليوم J+3 على سبيل المثال. أحد الحلول الممكنة لهذه المشكلة هو استخدام ملفات تعريف الارتباط. نحن نعلم أن رمز الجلسة بين الخادم والعميل يتم نقله عبر هذه الآلية. يمكننا أيضًا استخدام هذه الآلية لنقل المحاكيات بين العميل والخادم.
      • في نفس الوقت الذي يرسل فيه الخادم صفحة نتائج المحاكاة، يرسل في رؤوسه HTTP ملف تعريف ارتباط يحتوي على سلسلة أحرف تمثل المحاكاة. ونظرًا لأن هذه المحاكاة موجودة في كائن [ArrayList]، فإنه يتعين إجراء عملية تحويل هذا الكائن إلى [String]. ويحدد الخادم مدة صلاحية ملف تعريف الارتباط، على سبيل المثال 30 يومًا.
      • يقوم متصفح العميل بتخزين ملفات تعريف الارتباط المستلمة في ملف وإعادة إرسالها في كل مرة يقوم فيها بإرسال طلب إلى الخادم الذي أرسلها إليه إذا كانت لا تزال صالحة (لم تتجاوز مدة صلاحيتها). سيتلقى الخادم لسلسلة المحاكاة سلسلة أحرف [String] التي سيتعين عليه تحويلها إلى كائن [ArrayList].

    تتم إدارة ملفات تعريف الارتباط بواسطة [Response.Cookies] عند إرسالها إلى العميل وبواسطة [Request.Cookies] عند استلامها على الخادم.

    • قد تصبح الآلية السابقة ثقيلة إلى حد ما إذا كان هناك عدد كبير من عمليات المحاكاة. علاوة على ذلك، غالبًا ما يقوم المستخدم بمسح ملفات تعريف الارتباط بشكل دوري عن طريق حذفها جميعًا حتى لو كان قد سمح لمتصفحه باستخدامها. وبالتالي، في يوم من الأيام سنفقد ملف تعريف الارتباط الخاص بعمليات المحاكاة. قد نرغب عندئذٍ في تخزينها على الخادم بدلاً من العميل، في قاعدة بيانات على سبيل المثال. لربط المحاكاة بمستخدم معين، يمكن أن تبدأ التطبيق بمرحلة تحديد الهوية التي تتطلب اسم مستخدم وكلمة مرور مخزنين بدورهما في قاعدة بيانات أو أي نوع آخر من مخازن البيانات.
    • قد نرغب أيضًا في تأمين تشغيل تطبيقنا. يفترض التطبيق حاليًا أمرين:
      • يمر المستخدم دائمًا عبر وحدة التحكم [main.aspx]
      • وفي هذه الحالة، يستخدم دائمًا الإجراءات المقترحة في الصفحة التي تم إرسالها إليه

    ماذا يحدث، على سبيل المثال، إذا طلب المستخدم مباشرةً عنوان URL [http://localhost/impots4/formulaire.aspx]؟ هذه الحالة غير محتملة لأن المستخدم لا يعرف بوجود هذا الرابط. ومع ذلك، يجب توقعها. يمكن إدارتها بواسطة وحدة التحكم في التطبيق [global.asax] التي ترى جميع الطلبات الموجهة إلى التطبيق. وبذلك يمكنها التحقق من أن المورد المطلوب هو بالفعل [main.aspx].

    الحالة الأكثر احتمالاً هي أن المستخدم لا يستخدم الإجراءات الموجودة على الصفحة التي أرسلها له الخادم. على سبيل المثال، ماذا يحدث إذا طلب المستخدم عنوان URL [http://localhost/impots4/main.aspx?action=retour] مباشرةً دون ملء النموذج مسبقاً؟ لنجرب ذلك. نحصل على الرد التالي:

    حدث تعطل في الخادم. وهذا أمر طبيعي. بالنسبة للإجراء [retour]، يتوقع وحدة التحكم أن تجد في الجلسة كائنًا [NameValueCollection] يمثل قيم النموذج الذي يجب عليها عرضه. لكنها لا تجده. تتيح آلية وحدة التحكم تقديم حل أنيق لهذه المشكلة. لكل طلب، يمكن لوحدة التحكم [main.aspx] التحقق من أن الإجراء المطلوب هو بالفعل أحد الإجراءات الموجودة في الصفحة التي تم إرسالها مسبقًا إلى المستخدم. يمكن استخدام الآلية التالية:

    • يقوم وحدة التحكم، قبل إرسال ردها إلى العميل، بتخزين معلومات تحدد هوية هذه الصفحة في جلسة عمل العميل
    • عندما يتلقى طلبًا جديدًا من العميل، يتحقق من أن الإجراء المطلوب ينتمي بالفعل إلى آخر صفحة تم إرسالها إلى هذا العميل
    • يمكن إدخال المعلومات التي تربط بين الصفحات والإجراءات المسموح بها في هذه الصفحات في ملف التكوين [web.config] الخاص بالتطبيق.
    • تُظهر التجربة أن وحدات التحكم في التطبيقات لها قاعدة مشتركة واسعة وأنه من الممكن إنشاء وحدة تحكم عامة، حيث يتم تخصيصها لتطبيق معين عبر ملف التكوين. وهذا هو النهج الذي تتبعه، على سبيل المثال، الأداة [Struts] في مجال برمجة الويب بلغة Java.
